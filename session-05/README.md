# Session 05 · 서비스 아키텍처 종합 설계와 SAA-C03 문제 풀이

- **세션 일자:** 2026-12-29
- **제출 마감:** 2027-01-12 21:00 (KST)

앞선 세션에서 배운 기술을 종합해 최종 서비스 아키텍처를 설계하고, 성능·가용성·보안·비용을 점검합니다. SAA-C03 응용 문제를 풀며 요구 사항에 맞는 구성과 선택의 근거를 설명합니다.

## 학습 목표

- **실행 방식 선택:** EC2, ECS (Fargate), Lambda를 비교하고, 트래픽 패턴·운영 부담·비용에 따라 어떤 방식이 적합한지 설명합니다.
- **설계의 우선순위:** 하나의 아키텍처에서 성능·가용성·보안·비용 중 무엇을 우선했고, 어떤 제약을 받아들였는지 설명합니다.
- **요구 사항에 따른 판단:** SAA-C03 문제를 요구 사항 확인 → 후보 비교 → 선택과 배제의 근거 순서로 풀고, 그 판단을 서비스 설계에 적용합니다.

## 학습 범위

Session 02~04의 필수 학습 서비스 전체를 복습합니다. 새로운 AWS 서비스 학습을 추가하지 않으며, 최종 설계에는 요구 사항에 필요한 서비스를 선택해 조합합니다.

- **3-Tier 웹 서비스:** VPC, EC2, EC2 Auto Scaling, ELB (ALB), RDS
- **서버리스 이벤트 처리:** API Gateway, Lambda, DynamoDB, SQS, EventBridge
- **컨테이너와 배포:** ECS (Fargate), ECR, IAM, Secrets Manager, CodePipeline

## 종합 설계와 점검

앞선 세션의 문제 상황을 바탕으로, 개별 기능을 하나의 서비스 아키텍처로 연결합니다.

- **통합 아키텍처 그리기:** 요청이 들어오는 경로, 컴퓨트와 데이터 저장소의 연결, 이벤트 처리 흐름을 함께 표시합니다.
- **실행 방식 결정하기:** 기능별로 EC2, ECS (Fargate), Lambda 중 무엇을 사용할지 정하고, 트래픽 특성·운영 부담·비용을 근거로 설명합니다.
- **장애·보안·운영 점검하기:** 다중 AZ 구성과 백업, 오토스케일링 범위, 최소 권한과 자격 증명 관리, 중복 처리 방지와 재시도, 배포 실패 시 롤백을 점검합니다.
- **트레이드오프 비교하기:** 성능·가용성·보안·비용 사이에서 선택한 우선순위와 받아들인 제약을 정리하고, 다른 구성을 선택했을 때의 차이를 설명합니다.

## SAA-C03 응용 문제 풀이

다음 네 영역에서 대표 응용 문제를 하나씩 풀어봅니다. 요구 사항과 제약 조건을 읽고, 정답을 고른 근거와 다른 선택지를 배제한 이유를 설명합니다.

- **보안:** 서비스별 최소 권한, 자격 증명 관리, 네트워크 접근 범위를 판단합니다.
- **복원력:** AZ 장애, 배포 실패, 비동기 작업 실패에 맞는 복구·재시도 구성을 선택합니다.
- **고성능:** 트래픽 증가에 따른 컴퓨트 확장, 데이터 접근 방식, 비동기 처리 구성을 비교합니다.
- **비용 최적화:** 사용 패턴에 맞는 실행 방식과 용량 조정, 데이터베이스 용량 모드를 선택합니다.
