# Session 03 · 서버리스 이벤트 기반 서비스

- **세션 일자:** 2026-11-03
- **제출 마감:** 2026-11-17 21:00 (KST)

요청 처리와 후속 작업을 이벤트로 분리하고, 서버를 직접 운영하던 기능을 관리형 서비스로 구성합니다. 트래픽 급증과 중복 요청, 처리 실패와 재시도에도 데이터가 일관되게 처리되도록 설계합니다.

## 학습 목표

- **동기·비동기 처리:** 사용자가 결과를 즉시 기다려야 하는 작업과 접수만 확인한 뒤 나중에 처리해도 되는 작업을 구분합니다. 응답 지연과 작업 특성을 근거로 처리 방식을 선택합니다.
- **이벤트 기반 아키텍처:** 요청을 보내는 쪽과 처리하는 쪽을 이벤트로 느슨하게 연결하는 이유를 이해합니다. 메시지 큐가 작업을 버퍼링해 생산자와 소비자의 처리 속도 차이를 흡수하는 방식을 설명합니다.
- **서버리스 실행 모델:** 서버를 직접 운영하지 않고 요청이나 이벤트에 따라 코드를 실행하는 모델을 이해합니다. 콜드 스타트와 실행 시간 제한이 서비스에 미치는 영향을 살펴보고, 제한에 맞지 않는 작업의 대안을 검토합니다.
- **멱등성:** 같은 요청이나 메시지가 여러 번 도착해도 중복 결제·중복 처리가 발생하지 않도록 설계하는 개념을 이해합니다. 최소 한 번(at-least-once) 전달 방식에서 중복이 생길 수 있음을 고려해 조건부 쓰기와 중복 제거 방식을 설명합니다.
- **실패 처리:** 실패한 작업의 재시도, 처리 중인 메시지를 일시적으로 숨기는 가시성 제한 시간, 반복 실패한 메시지를 격리하는 데드레터큐(DLQ)의 역할을 구분합니다.

동기 처리로 인한 응답 지연과 중복 처리 문제를 짚어내고, 이벤트 분리·멱등성·재시도와 DLQ를 조합해 개선안을 설계하는 것이 목표입니다.

## 학습 범위

아래 5개 서비스가 필수 학습 범위입니다. 문제 해결에 필요한 서비스는 추가로 활용할 수 있습니다.

- **API Gateway:** 스로틀링, 사용량 계획, Lambda 통합, 인증 연동
- **Lambda:** 실행 역할, 동시성, 콜드 스타트, 실행 시간 제한과 대안
- **DynamoDB:** 파티션 키와 핫 파티션, 조건부 쓰기, 온디맨드와 프로비저닝, Streams
- **SQS:** 비동기 버퍼링, 가시성 제한 시간, 재시도와 DLQ, FIFO와 중복 제거
- **EventBridge:** 이벤트 라우팅, 규칙과 대상, SQS·SNS와의 역할 구분

## 문제 상황 예시

아래는 학습 범위를 적용해 볼 수 있는 설계 예시입니다.

### 좌석 하나가 두 명에게 팔리는 티켓 예매

판매 시작 직후 요청이 집중되고, 같은 좌석이 두 번 예매되거나 새로고침한 사용자에게 결제가 중복 청구됩니다.

조건부 쓰기로 좌석의 중복 예매를 어떻게 막을지, 재요청이나 메시지 중복 전달에도 결제가 한 번만 반영되도록 멱등성을 어떻게 확보할지 검토합니다. 즉시 결과를 반환할 작업과 비동기로 처리할 후속 작업도 구분합니다.

### 긴 영상에서 멈추는 업로드 처리

썸네일 생성·인코딩·자막 추출을 한 함수가 순차적으로 처리하다 실행 시간 제한에 걸립니다. 일부 단계만 실패해도 전체 작업을 처음부터 다시 실행해야 합니다.

작업을 어떤 단위로 분리하고 이벤트로 연결할지, 실패한 단계만 어떻게 재시도할지 설계합니다. 함수의 실행 시간 제한에 맞지 않는 작업의 대안과 반복 실패한 작업을 DLQ로 격리하는 흐름도 함께 검토합니다.
