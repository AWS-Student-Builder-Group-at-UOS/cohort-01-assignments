# ASBG UOS 1기 과제

AWS를 직접 만들어 보고, 선택한 이유와 확인한 결과를 기록합니다.

**한 사람 · 한 회차 · 하나의 PR**로 제출합니다. 코어팀이 PR에 피드백을 남기고, 확인이 끝나면 저장소에 반영합니다. 과제는 자율이며 수료의 필수 조건이 아닙니다.

## 제출 방법

GitHub 웹 화면에서 제출할 수 있습니다. 아래 예시는 Session 02, GitHub ID가 `my-id`인 경우입니다.

1. **처음 한 번 Fork:** 이 저장소 오른쪽 위의 **Fork**를 눌러 개인 계정에 복사합니다.
2. **회차별 새 브랜치:** 내 Fork의 `main`에서 **Sync fork → Update branch**로 동기화합니다. 브랜치 선택 메뉴에서 `session-02/my-id` 브랜치를 만듭니다. 이미 최신이면 동기화는 건너뜁니다.
3. **과제 작성:** [기존 템플릿](assignment-template.md)을 복사해 아래 구조로 준비합니다. 네 항목을 모두 작성하고, 스크린샷은 문서에 연결합니다.
4. **파일 업로드:** 내 Fork의 새 브랜치 루트에서 **Add file → Upload files**를 선택합니다. 준비한 `session-02` 폴더를 끌어 넣고, 경로가 아래와 같은지 확인한 뒤 **Commit changes**로 저장합니다. 이번 과제의 본인 폴더만 올립니다.
5. **PR 제출:** **Contribute → Open pull request**를 선택합니다. 대상은 **조직의 `cohort-01-assignments` / `main`**, 출발은 **내 Fork / `session-02/my-id`**인지 확인합니다. 제목을 `[Session 02] 홍길동 과제 제출`로 쓰고 **Create pull request**를 누릅니다.

```text
session-02/
└── my-id/
    ├── README.md
    └── images/
        └── result.png
```

문서의 이미지는 `![완료 조건 확인 결과](images/result.png)`처럼 연결합니다. 과제 본문과 증빙은 PR 설명에만 붙이지 않고 파일로 제출합니다.

**다음 회차도 동기화한 `main`에서 새 브랜치를 만드세요.** 이전 과제 브랜치를 재사용하거나 내 Fork의 `main`에 과제를 작성하면 여러 회차의 변경이 한 PR에 섞일 수 있습니다.

## 피드백과 수정

- 코어팀이 PR 코멘트로 잘한 점, 보완 제안, 확인이 필요한 내용을 남깁니다. 직접 리뷰어를 지정할 필요는 없습니다.
- 수정은 **같은 브랜치의 같은 파일**에 반영합니다. 열려 있는 PR이 갱신되므로 새 PR을 만들지 않습니다.
- 추가 실습 등 보완 제안은 선택입니다. 필수 항목 누락·깨진 이미지처럼 확인에 필요한 부분은 수정해 주세요. 미완성인 부분도 실제 상태와 확인 결과를 적으면 됩니다.
- 코어팀이 피드백하고 승인한 뒤 머지합니다. **머지는 피드백 완료와 기록 보관을 뜻하며, 점수나 과제 완성도를 뜻하지 않습니다.**

| PR 상태 | 의미 |
|---|---|
| Open | 제출됨 · 피드백 또는 수정 진행 중 |
| Merged | 피드백 완료 · 저장소에 반영됨 |

제출은 **Draft가 아닌 PR을 연 시점**에 접수됩니다. Draft로 만들었다면 **Ready for review**를 누른 시점부터 접수됩니다. 코어팀의 머지 시점은 마감 여부에 영향을 주지 않습니다. 머지 이후 보완은 새 PR 제목에 `보완`을 표시하고 기존 PR 번호를 연결해 주세요.

## 마감과 우수 과제

우수 과제는 마감 전에 접수된 PR의 **마감 시점 문서와 이미지**로 평가합니다. 마감까지 같은 PR에서 수정할 수 있으며, 마감 후 수정은 시상 평가에 반영하지 않습니다. 코어팀은 마감본을 보존한 뒤 피드백을 진행합니다. 지각 제출도 피드백을 받지만 해당 회차 시상 대상에서는 제외됩니다.

평가 기준은 완료 조건 **40점**, 선택 근거 **35점**, 검증·문제 해결 **25점**입니다. 문제가 없었어도 정상 동작을 충분히 검증하면 검증 항목 만점을 받을 수 있습니다. [평가 방식과 시상 안내](EVALUATION.md)에서 전체 기준을 확인하세요.

이 저장소의 제출물과 코멘트는 공개됩니다. AWS 키·비밀번호·개인정보는 문서와 이미지에 포함하지 않고, 실습 후에는 불필요한 리소스를 정리해 주세요.
