# Session 02 · 안정적인 수강신청 포털을 위한 3-Tier 인프라 설계

- **세션 일자:** 2026-09-29
- **제출 마감:** 2026-10-13 21:00 (KST)

## 문제 상황

대학교에서 다음 학기 수강신청을 앞두고 포털 인프라를 개선하려고 합니다. 지난 학기에는 다음과 같은 문제가 발생했습니다.

1. **로그인 끊김**  
   APP 서버를 두 대로 운영했지만, 강의를 조회하거나 신청 화면으로 이동하면 간헐적으로 로그인이 풀렸습니다. 서버 재시작·교체 시에도 로그인 상태가 유지되지 않았습니다.

2. **장애 대응 지연**  
   APP 한 대가 응답하지 않아도 해당 서버로 요청이 계속 전달되었습니다. 장애 서버를 자동으로 교체하는 구성도 없어 운영자가 직접 조치해야 했습니다.

3. **접속량 변화에 대응하지 못하는 서버 구성**  
   신청 시작 직후 요청이 집중되어 응답 지연과 오류가 발생했습니다. 서버를 수동으로 추가하느라 대응이 늦었고, 신청 종료 후에도 추가 서버가 남아 비용이 발생했습니다.

## 과제

위 문제를 해결하는 **WEB·APP·DB 기반의 3-Tier 아키텍처를 설계하세요.**

- APP이 추가·제거되거나 요청이 다른 APP으로 전달되어도 로그인 상태를 유지하는 방법
- 장애 서버를 감지·제외하고 정상 서버로 서비스를 지속하며 자동 복구하는 방법
- 수강신청 시작 시점의 부하에 대비하고, 요청량에 따라 서버 수를 조정하는 방법

위 항목의 동작 방식과 선택 이유를 설명하세요. 다중 AZ 배치, 계층별 접근 제어, 데이터 보호도 함께 고려합니다.

설계에는 **VPC, EC2, EC2 Auto Scaling, ALB, RDS를 필수로 포함**하며, 필요한 서비스는 추가할 수 있습니다.
