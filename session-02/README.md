# Session 02 · 3-Tier 웹 서비스 구축

- **세션 일자:** 2026-09-29
- **제출 마감:** 2026-10-13 21:00 (KST)

VPC의 네트워크 구성부터 시작해 웹·애플리케이션·데이터베이스 계층을 나눕니다. 한 리전 안에서 트래픽 증가와 가용 영역(AZ) 장애에 대응할 수 있도록 계층별 확장과 데이터 보호를 설계합니다.

## 학습 목표

- **네트워크 기초:** IP 대역을 서브넷으로 나누는 이유와 라우팅 테이블이 트래픽 경로를 결정하는 방식을 이해합니다. 보안 그룹의 상태 저장(stateful) 방식과 NACL의 상태 비저장(stateless) 방식을 비교합니다.
- **계층 분리:** 웹·앱·DB를 한 서버에 운영할 때 생기는 장애와 확장 문제를 파악하고, 계층을 나누어 장애를 격리하고 독립적으로 확장하는 이유를 설명합니다.
- **로드밸런싱:** 리버스 프록시의 요청 분산·헬스체크 역할과 관리형 ALB의 역할을 연결해 이해합니다. 세션 등 상태가 특정 인스턴스에 종속되지 않는 스테이트리스 설계가 요청 분산과 수평 확장에 유리한 이유를 설명합니다.
- **수평 확장:** 서버 사양을 높이는 스케일업과 서버 대수를 늘리는 스케일아웃을 구분합니다. EC2 Auto Scaling으로 부하에 맞춰 인스턴스 수를 조정하고 비정상 인스턴스를 교체하는 흐름을 이해합니다.
- **데이터 이중화:** 데이터를 다른 곳에 복제하는 것과 특정 시점의 백업을 남기는 것의 차이를 이해합니다. Multi-AZ, 읽기 전용 복제본, 백업의 목적을 구분하고 장애 대응과 데이터 복구에 필요한 구성을 설명합니다.

단일 서버 구성의 단일 장애점(SPOF)을 짚어내고, 계층 분리·로드밸런싱·오토스케일링·DB 이중화를 조합해 개선안을 설계하는 것이 목표입니다.

## 학습 범위

아래 5개 서비스가 필수 학습 범위입니다. 문제 해결에 필요한 서비스는 추가로 활용할 수 있습니다.

- **VPC:** 퍼블릭·프라이빗 서브넷, 라우팅 테이블, 보안 그룹과 NACL, NAT Gateway
- **EC2:** 인스턴스 타입 선택, EBS, AMI, 사용자 데이터
- **EC2 Auto Scaling:** 시작 템플릿, 조정 정책, 상태 확인 기반 인스턴스 교체
- **ELB (ALB):** 리스너와 대상 그룹, 다중 AZ 트래픽 분산, 스테이트리스 설계
- **RDS:** Multi-AZ와 읽기 전용 복제본의 차이, 서브넷 그룹, 백업

## 문제 상황 예시

아래는 학습 범위를 적용해 볼 수 있는 설계 예시입니다.

### 학기 초마다 멈추는 중고거래 사이트

EC2 한 대에 웹·앱·DB를 모두 운영하고 있습니다. 개강 주에 동시 접속자가 평시 50명에서 800명으로 늘면서 서비스가 중단되고 게시글 일부가 유실됩니다.

웹·앱·DB를 어떻게 분리하고 각 계층의 접근 범위를 제한할지, 늘어난 요청을 어떻게 분산하고 인스턴스를 확장할지 검토합니다. AZ 장애에 대비한 구성과 게시글 보호·복구 방안도 함께 설계합니다.

### 오픈 직후 트래픽이 몰리는 수강 신청

신청 시작 후 3분에 트래픽의 90%가 집중되며, 접속 장애와 정원 초과 등록이 반복됩니다.

짧은 시간에 몰리는 트래픽에 맞춰 인프라를 어떻게 확장할지 검토합니다. 여러 서버가 동시에 신청을 처리해도 정원을 초과하지 않도록 데이터 정합성을 지키는 방법을 함께 고려합니다.
